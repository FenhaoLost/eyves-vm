# 第六部分：功能说明

> 本文回答"到底有什么功能、哪些现在能用"。
> 图例：✅ 已实现可用 · 📐 设计态（接口已定稿，无实现） · ⏳ 规划中（仅记录） · ❌ 明确不做

**一句话结论**：当前**能直接用**的是 cub-panel（本仓库外）；Eyves VM 自身只实现了计费域，**没有任何 HTTP 接口可供调用**。

### 6.2.6 镜像与模板（📐 设计态）

现状（6.1.5）只有 simplestreams 一条路，节点自行拉取，套餐白名单控制可见性。缺口是**无法引入 simplestreams 之外的系统镜像**。

| 能力 | 状态 | 说明 |
|---|---|---|
| simplestreams 来源 | 📐 | 别名 + 源站地址，兼容现状行为；同一别名带容器与 VM 两种变体 |
| **URL 直链导入** | 📐 | **新增**。sha256 必填，缺失返回 `EYVES-709` |
| **本地上传** | 📐 | **新增**。分片上传，`Content-Range` 幂等可续传，32 GiB 上限 |
| **推 / 拉两种分发** | 📐 | **新增**。`pull` 默认（与现状兼容）；`push` 供内网无外网节点，主控入仓后推送 |
| **分发 / 预热** | 📐 | 幂等；新节点上线可批量预热，避免首位客户同步等下载 |
| **上游更新策略** | 📐 | `pin`（默认，不落盘） / `track`（跟随）；**已存在实例引用的产物永不就地替换** |
| **对账** | 📐 | 周期拉取节点实际持有情况，纠正 placements 漂移 |
| 格式探测 | 📐 | **读 magic bytes，不信任扩展名**（qcow2 / gzip / xz） |
| 删除保护 | 📐 | 被实例引用时 `409` + `EYVES-705`，`force` 不可绕过 |
| 套餐可见性 | 📐 | 归 `catalog.Plan.image_ids`，**不在 image 模块内**（避免双事实源） |

## 6.3 第 3 层：规划中（⏳ 仅记录）

| 功能 | 为什么暂不做 |
|---|---|

| 资源池 / 超卖比控制 | 策略层能力，待调度器落地后评估 |

## 6.5 明确不做（❌ YAGNI）

| 项 | 理由 |
|---|---|
| 多活主控 / 分布式 SQLite | 与"SQLite 单文件、单机"硬约束冲突；集群需求走 PostgreSQL 扩展接口 |
| 自建对象存储 | 与虚拟化核心无关 |
| 内置工单 / 知识库 | 边界外，鼓励对接现成系统 |
| GUI 拖拽式编排 | 复杂度远超收益 |
| 替换被控端协议 | 协议冻结是硬约束，复用 cub-agent |

## 6.6 从"现状"到"目标"要补的活

按依赖顺序：

1. **存储适配器** —— 为 `Ledger` / `OrderRepo` 写 SQLite 实现（解锁真实的 89.3% → 端到端覆盖）
2. **`cmd/` 入口 + `internal/app` 装配** —— 目前没有任何 `main.go`
3. **`/v2` 路由 + HTTP 层** —— 领域错误 → HTTP 状态码映射
4. **Hypervisor 抽象层实现** —— 先做 Incus 适配器（复用 cub-agent）
5. **image 模块** —— 三种来源 + 分发 + 对账。**接 KVM 前必须先做**：libvirt 没有 simplestreams，KVM 的镜像必须靠 URL 导入 / 上传供给
6. **catalog 模块** —— 套餐多周期定价（计费域已就绪，缺目录）
7. **instance 模块** —— 实例生命周期 + 与计费域的购买编排打通
8. **network / snapshot 模块**
9. **cluster 模块** —— 节点注册、健康检查、调度、迁移
10. **Web UI** —— 现有 cub-panel 模板改造或重写

详细排期与风险见 [05-risks.md](05-risks.md)。
